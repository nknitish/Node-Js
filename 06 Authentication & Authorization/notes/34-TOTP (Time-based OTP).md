# TOTP (Time-based One-Time Password)

> **Interview Definition:**  
> **TOTP (Time-based One-Time Password)** is a two-factor authentication (2FA) method that generates a **temporary 6-digit code** based on a **shared secret key** and the **current time**. The code changes every **30 seconds**, making it much more secure than static passwords.

> **One-line Interview Answer:**  
> **TOTP is a time-based OTP algorithm used for 2FA where both the server and authenticator app generate the same OTP using a shared secret and the current time.**

# 1. What is TOTP?

TOTP is a **second authentication factor**.

Instead of

```text
Password

↓

Login
```

You use

```text
Password

+

6-digit OTP

↓

Login
```

The OTP changes every 30 seconds.

Example

```text
10:00:00

↓

483291

-------------------

10:00:30

↓

927441

-------------------

10:01:00

↓

182034
```

# 2. Why Do We Need TOTP?

Suppose someone steals your password.

Without 2FA

```text
Password

↓

Login

✔
```

With TOTP

```text
Password

↓

Enter OTP

↓

No OTP

↓

Login Failed
```

```text

↓

Stores Secret

↓

Every 30 Seconds

↓

Generate OTP

↓

User Enters OTP

↓

Server Generates OTP

↓

Compare

↓

Match?

```

Notice

The server never sends the OTP.

Both sides independently generate it.

# 8. Express.js Implementation

Install

```bash
pnpm add speakeasy qrcode
```

Generate Secret

```javascript
import speakeasy from "speakeasy";

const secret = speakeasy.generateSecret({
  name: "MyApp",
});

console.log(secret.base32);
```

Generate QR Code

```javascript
import QRCode from "qrcode";

QRCode.toDataURL(secret.otpauth_url).then(console.log);
```

Verify OTP

```javascript
const verified = speakeasy.totp.verify({
  secret: user.secret,

  encoding: "base32",

  token: req.body.otp,
});

if (verified) {
  console.log("OTP Valid");
}
```

# 12. Best Practices

✅ Store secret securely.

✅ Use HTTPS.

✅ Allow small time drift (±1 time window).

✅ Generate backup recovery codes.

✅ Require 2FA for admin accounts.

✅ Never send the secret to the frontend after setup.

---

### Does TOTP require internet?

No.

Only the initial setup requires communication with the server.

---

### Why does OTP change every 30 seconds?

Because the algorithm uses the current time as an input.

---

### Is the OTP stored in the database?

No.

The server stores only the secret key.

---

### Which algorithm does TOTP use?

TOTP is defined in RFC 6238 and is built on the HOTP algorithm (RFC 4226), using the current time as the moving factor.

# 15. Interview Answer

> **TOTP (Time-based One-Time Password) is a two-factor authentication mechanism that generates a temporary one-time password using a shared secret key and the current time. When a user enables 2FA, the server generates a secret key and provides it as a QR code. The user scans the QR code using an authenticator app such as Google Authenticator or Microsoft Authenticator. During login, both the server and the authenticator independently generate the same OTP using the shared secret and the current time. If the entered OTP matches the server's calculation, the user is authenticated. Since the OTP changes every 30 seconds and is never transmitted by the server, TOTP provides strong protection against stolen passwords.**

# ⭐ Most Asked Interview Questions

### Q1. Does the server send the OTP?

**No.**

The server sends only the **secret** during the initial setup.

After that:

```text
Server

↓

Secret

+

Current Time

↓

Generate OTP
```

The authenticator app performs the same calculation independently.

---

### Q2. Why is TOTP more secure than SMS OTP?

TOTP:

- Works offline
- Isn't vulnerable to SIM swap attacks
- Doesn't rely on SMS delivery
- Uses a shared cryptographic secret

---

### Q3. What happens if the user's phone clock is slightly different?

Most implementations allow a small **time window** (typically ±30 seconds) to account for minor clock differences before rejecting the OTP.

---

### Q4. How do companies implement TOTP?

A typical production flow is:

```text
Enable 2FA

↓

Generate Secret

↓

Save Secret

↓

Generate QR Code

↓

User Scans

↓

Login

↓
```

This is the standard approach used by services such as GitHub, AWS, Microsoft, and many banking applications.
