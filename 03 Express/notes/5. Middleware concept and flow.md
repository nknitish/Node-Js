# Express.js Middleware (Concept & Flow)

> **Interview Definition:**
> **Middleware** is a function in Express that executes **between the incoming HTTP request and the final route handler**. It has access to the **Request (`req`)**, **Response (`res`)**, and the **`next()`** function. Middleware can modify requests, execute business logic, authenticate users, log requests, validate data, or terminate the request-response cycle.

# 1. What is Middleware?

Middleware is simply a **JavaScript function**.

It runs **before** the final route handler.

Example:

```text
Client

↓

Request

↓

Middleware

↓

Route Handler

↓

Response
```

Without middleware:

```text
Request

↓

Route

↓

Response
```

With middleware:

```text
Request

↓

Logging

↓

Authentication

↓

Validation

↓

Route

↓

Response
```

---

# 2. Why Do We Need Middleware?

Imagine every route performs authentication.

Without middleware:

```js
app.get("/users", (req, res) => {
  // Authentication
  // Validation
  // Logging
});

app.get("/products", (req, res) => {
  // Authentication
  // Validation
  // Logging
});
```

The same code is repeated.

Instead:

```text
Request

↓

Authentication Middleware

↓

Validation Middleware

↓

Logging Middleware

↓

Route
```

Now every route can reuse the same logic.

```text

↓

↓

Middleware 1

↓
```

Every middleware decides:

- End the request (`res.send()`)
- Pass an error (`next(err)`)

# 4. Middleware Function

Syntax:

```js
(req, res, next) => {};
```

Example:

```js
import express from "express";

const app = express();

function logger(req, res, next) {
  console.log("Request Received");

  next();
}

app.use(logger);

app.get("/", (req, res) => {
  res.send("Home");
});

app.listen(3000);
```

Output:

```text
Request Received

Home
```

---

# 5. The `next()` Function

`next()` tells Express:

> "I'm done. Continue to the next middleware."

Example:

```js
function middleware(req, res, next) {
  console.log("Middleware");

  next();
}
```

Flow:

```text
Request

↓

Middleware

↓

next()

↓

Route

↓

Response
```

---

### What Happens Without `next()`?

```js
function middleware(req, res, next) {
  console.log("Hello");
}
```

Request:

```text
Client

↓

Middleware

↓

Stops Here
```

The browser keeps waiting because neither `next()` nor a response was sent.

# 6. Types of Middleware

Express supports several types of middleware.

| Type                   | Purpose                  |
| ---------------------- | ------------------------ |
| Application Middleware | Runs for the application |
| Route Middleware       | Runs for specific routes |
| Built-in Middleware    | Provided by Express      |
| Third-party Middleware | External packages        |
| Error Middleware       | Handles errors           |

---

# 7. Application-level Middleware

Runs for every request (unless limited by path).

```js
app.use((req, res, next) => {
  console.log(req.method);

  next();
});
```

Request:

```text
/users

/products

/orders
```

Runs for all of them.

---

# 8. Route-level Middleware

Runs only for selected routes.

```js
function auth(req, res, next) {
  console.log("Authenticated");

  next();
}

app.get("/dashboard", auth, (req, res) => {
  res.send("Dashboard");
});
```

Flow:

```text
/dashboard

↓

Auth

↓

Dashboard
```

# 9. Built-in Middleware

## Parse JSON

```js
app.use(express.json());
```

Without this:

```js
req.body;
```

is usually `undefined` for JSON requests.

---

## Parse URL-Encoded Data

```js
app.use(
  express.urlencoded({
    extended: true,
  }),
);
```

Used for HTML form submissions.

---

## Serve Static Files

```js
app.use(express.static("public"));
```

Folder:

```text
public/

├── logo.png

├── style.css

└── app.js
```

Visit:

```text
http://localhost:3000/logo.png
```

# 11. Error-handling Middleware

Error middleware has **four parameters**.

```js
app.use((err, req, res, next) => {
  console.error(err);

  res.status(500).json({
    message: "Something Went Wrong",
  });
});
```

Notice:

```js
(err, req, res, next);
```

The first parameter is always `err`.

---

# 12. Middleware Execution Order

Middleware runs **in the order it is registered**.

```js
app.use(first);

app.use(second);

app.use(third);
```

Execution:

```text
first

↓

second

↓

third
```

Order matters.

---

# Example

```js
app.use((req, res, next) => {
  console.log("1");

  next();
});

app.use((req, res, next) => {
  console.log("2");

  next();
});

app.get("/", (req, res) => {
  console.log("3");

  res.send("Done");
});
```

Output:

```text
1

2

3
```

# 14. Common Middleware Examples

## Logger

```js
function logger(req, res, next) {
  console.log(req.method);

  next();
}
```

---

## Authentication

```js
function auth(req, res, next) {
  if (!req.headers.authorization) {
    return res.status(401).send("Unauthorized");
  }

  next();
}
```

---

## Validation

```js
function validate(req, res, next) {
  if (!req.body.name) {
    return res.status(400).send("Name Required");
  }

  next();
}
```

# 16. Common Interview Questions

### What is Middleware?

A function that executes during the request-response cycle before the final route handler.

---

### What is `next()`?

A function that passes control to the next middleware or route handler.

---

### What happens if `next()` isn't called?

If the middleware neither calls `next()` nor sends a response, the request remains pending and the client waits until it times out.

---

### Does middleware execute in order?

Yes.

Express executes middleware in the order it is registered.

---

### Difference between `app.use()` and `app.get()`?

| `app.use()`                       | `app.get()`         |
| --------------------------------- | ------------------- |
| Register middleware               | Handle GET requests |
| Can run for multiple HTTP methods | Only handles GET    |

---

### Why use middleware?

To avoid repeating logic such as authentication, logging, validation, and parsing across multiple routes.

# 18. Interview Answer

> **Middleware in Express is a function that executes during the request-response cycle. It has access to the request object (`req`), response object (`res`), and the `next()` function. Middleware is commonly used for tasks such as logging, authentication, validation, parsing request bodies, serving static files, and error handling. Middleware executes in the order it is registered. It can either pass control to the next middleware using `next()`, send a response to end the request, or forward an error using `next(err)`. This design promotes code reuse, separation of concerns, and maintainable application architecture.**
