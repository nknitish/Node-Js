# Express.js Middleware Execution Order

> **Interview Definition:**
> **Middleware Execution Order** refers to the sequence in which Express executes middleware and route handlers. Express processes middleware **from top to bottom** in the exact order they are registered. The order is critical because each middleware can modify the request, send a response, or pass control to the next middleware using `next()`.

# 1. What is Middleware Execution Order?

Express executes middleware **in the order it is registered**.

Example:

```js
app.use(first);

app.use(second);

app.use(third);
```

Execution:

```text id="9zmhcn"
Request

↓

first()

↓

second()

↓

third()

↓

Route Handler

↓

Response
```

Express **does not** rearrange middleware based on type or priority.

---

# 2. Why Does Order Matter?

Suppose authentication runs **after** the controller.

```text id="avtdnx"
Request

↓

Controller

↓

Authentication
```

The controller executes before verifying the user.

Correct order:

```text id="a7jlwm"
Request

↓

Authentication

↓

Controller

↓

Response
```

The user is verified before accessing protected resources.

# 3. Internal Execution Flow

```text id="ud0m8n"
HTTP Request

        │

        ▼

Middleware 1

        │

      next()

        ▼

Middleware 2

        │

      next()

        ▼

Middleware 3

        │

      next()

        ▼

Matching Route

        │

        ▼

Controller

        │

        ▼

Response
```

Each middleware decides whether to:

- Continue with `next()`
- End the request with `res.send()` / `res.json()`
- Pass an error with `next(err)`

# 4. Basic Example

```js
import express from "express";

const app = express();

app.use((req, res, next) => {
  console.log("Middleware 1");

  next();
});

app.use((req, res, next) => {
  console.log("Middleware 2");

  next();
});

app.get("/", (req, res) => {
  console.log("Controller");

  res.send("Home");
});
```

Output:

```text id="u5y2xt"
Middleware 1

Middleware 2

Controller
```

# 6. Global vs Route Middleware

```js
app.use(logger);

  res.send("Profile");
});
```

Flow:

```text id="jlwm1"
Request

↓

Logger

↓

Authentication

↓

Controller

↓

Response
```

Global middleware runs first because it was registered first.

# 7. Path-specific Middleware

```js
app.use("/admin", auth);

app.get("/admin", (req, res) => {
  res.send("Admin");
});

app.get("/", (req, res) => {
  res.send("Home");
});
```

Request:

```text id="jlwm2"
GET /

↓

Home
```

Authentication is skipped.

Request:

```text id="jlwm3"
GET /admin

↓

Authentication

↓

Admin

↓

Response
```

Only matching paths execute the middleware.

# 8. Route Matching Order

Routes are checked **from top to bottom**.

Wrong:

```js
app.get("/:id", (req, res) => {
  res.send(req.params.id);
});

app.get("/about", (req, res) => {
  res.send("About");
});
```

Request:

```text id="jlwm4"
/about
```

Matches:

```text id="jlwm5"
:id
```

Output:

```text id="jlwm6"
about
```

Correct:

```js
app.get("/about", (req, res) => {
  res.send("About");
});

app.get("/:id", (req, res) => {
  res.send(req.params.id);
});
```

Express uses the **first matching route**.

# 9. Error Middleware Order

Error middleware should generally be registered **after** normal routes and middleware.

```js
app.get("/", (req, res) => {
  throw new Error("Oops");
});

app.use((err, req, res, next) => {
  res.status(500).json({
    message: err.message,
  });
});
```

Flow:

```text id="jlwm7"
Request

↓

Route

↓

Error

↓

Error Middleware

↓

Response
```

# 11. Best Practices

Register middleware in this order:

```js
app.use(morgan("dev"));

app.use(cors());

app.use(express.json());

app.use(express.urlencoded({ extended: true }));

app.use("/api/users", userRoutes);

app.use("/api/products", productRoutes);

app.use(errorHandler);
```

Recommended sequence:

1. Logging
2. Security
3. Body parsers
4. Static files (if needed)
5. Routes
6. Error handler

# 12. Common Mistakes

## Wrong Order

```js
app.get("/", controller);

app.use(express.json());
```

Problem:

```text id="jlwm9"
req.body

↓

undefined
```

Because the JSON parser was registered after the route.

Correct:

```js
app.use(express.json());

app.get("/", controller);
```

---

## Route Before Middleware

```js
app.get("/profile", controller);

app.use(auth);
```

The authentication middleware never runs for `/profile`.

Correct:

```js
app.use(auth);

app.get("/profile", controller);
```

---

## Error Middleware Before Routes

```js
app.use(errorHandler);

app.get("/", controller);
```

The error handler won't catch errors from routes registered afterward in the intended way. Place it after routes.

# 13. Common Interview Questions

### How does Express execute middleware?

From top to bottom, in the order they are registered.

---

### Does middleware priority exist?

No.

Execution order depends on registration order.

---

### What runs first: `app.use()` or route middleware?

Whichever is registered first. In common applications, global `app.use()` middleware is registered before routes.

---

### Why should `express.json()` come before routes?

So JSON request bodies are parsed before route handlers access `req.body`.

---

### Where should the error middleware be placed?

Typically at the end of the middleware and route registration chain.

---

# 14. Quick Revision

| Registered First          | Executes First            |
| ------------------------- | ------------------------- |
| `app.use(logger)`         | ✅                        |
| `app.use(cors())`         | ✅                        |
| `app.use(express.json())` | ✅                        |
| `app.get()`               | After previous middleware |
| Error Handler             | Usually last              |

# 15. Interview Answer

> **Express executes middleware and routes sequentially in the order they are registered. Each middleware can either continue the request by calling `next()`, end the request by sending a response, or pass an error using `next(err)`. Because Express processes middleware from top to bottom, registration order is critical. Global middleware such as logging, CORS, and body parsers are typically registered before routes, while error-handling middleware is placed at the end so it can handle errors generated during request processing.**
