# Express.js `next()` Function

> **Interview Definition:**
> The **`next()`** function is a callback provided by Express that tells the framework to **pass control to the next middleware or route handler** in the request-response cycle. Without calling `next()` (or sending a response), the request will remain pending.

# 1. What is `next()`?

Every Express middleware receives three parameters:

```js
(req, res, next);
```

- `req` → Request Object
- `res` → Response Object
- `next` → Function to continue the request

Think of `next()` as saying:

> **"My work is done. Execute the next middleware or route handler."**

---

# 2. Why Do We Need `next()`?

Suppose your application has:

- Logger
- Authentication
- Validation
- Controller

Flow:

```text
Client

↓

Logger

↓

Authentication

↓

Validation

↓

Controller

↓

Response
```

How does Express know when one middleware has finished?

The answer is **`next()`**.

---

# 3. Internal Flow

```text
HTTP Request

        │

        ▼

Middleware 1

        │

     next()

        ▼

Middleware 2

        │

     next()

        ▼

Middleware 3

        │

     next()

        ▼

Route Handler

        │

        ▼

Response
```

Every middleware decides whether to:

- Continue → `next()`
- End request → `res.send()`
- Pass an error → `next(err)`

# 4. Basic Example

```js
import express from "express";

const app = express();

function logger(req, res, next) {
  console.log("Logger Middleware");

  next();
}

app.use(logger);

app.get("/", (req, res) => {
  res.send("Home Page");
});

app.listen(3000);
```

Output

```text
Logger Middleware

Home Page
```

Flow

```text
Request

↓

Logger

↓

next()

↓

Route

↓

Response
```

# 5. What Happens Without `next()`?

Example:

```js
function logger(req, res, next) {
  console.log("Logging Request");
}
```

Route

```js
app.use(logger);

app.get("/", (req, res) => {
  res.send("Home");
});
```

Flow

```text
Request

↓

Logger

↓

Stops Here ❌
```

Result

- Browser keeps loading
- No response is sent
- Request eventually times out

Because:

- `next()` wasn't called
- `res.send()` wasn't called

# 8. Using `next(err)`

If something goes wrong, pass the error.

```js
function auth(req, res, next) {
  if (!req.headers.authorization) {
    return next(new Error("Unauthorized"));
  }

  next();
}
```

Error Handler

```js
app.use((err, req, res, next) => {
  res.status(401).json({
    error: err.message,
  });
});
```

Flow

```text
Request

↓

Authentication

↓

next(err)

↓

Error Middleware

↓

Response
```

---

# 9. Ending the Request Instead

A middleware can stop the request by sending a response.

```js
function auth(req, res, next) {
  if (!req.headers.authorization) {
    return res.status(401).send("Unauthorized");
  }

  next();
}
```

Flow

```text
Request

↓

Authentication

↓

Unauthorized

↓

Response

↓

Stops
```

Notice:

`next()` is **not** called after sending the response.

# 10. Common Mistakes

## Forgetting `next()`

```js
app.use((req, res, next) => {
  console.log("Hello");
});
```

Result:

```text
Browser Loading Forever
```

---

## Calling `next()` After Sending a Response

Wrong:

```js
res.send("Hello");

next();
```

Possible Error

```text
Error: Cannot set headers after they are sent to the client
```

Choose one:

- Send a response
- OR call `next()`

---

## Calling `next()` Twice

Wrong:

```js
next();

next();
```

This can cause unexpected behavior or errors because Express may continue processing the same request multiple times.

# 12. Best Practices

✅ Call `next()` when middleware finishes and should continue.

✅ Use `return res.status(...).send(...)` when ending the request early.

✅ Use `next(err)` to delegate error handling to Express error middleware.

❌ Don't call `next()` after sending a response.

❌ Don't forget `next()` in middleware that should continue processing.

❌ Don't call `next()` multiple times.

---

# 13. Common Interview Questions

### What is `next()`?

A function that passes control to the next middleware or route handler.

---

### When should we call `next()`?

When the current middleware has finished its work and the request should continue.

---

### What happens if `next()` isn't called?

If the middleware also doesn't send a response, the request remains pending and the client waits until it times out.

---

### What is `next(err)`?

It forwards an error to Express error-handling middleware.

---

### Should we call `next()` after `res.send()`?

No.

Once a response has been sent, the request-response cycle is complete.

---

# 14. Quick Revision

| Function                        | Purpose                          |
| ------------------------------- | -------------------------------- |
| `next()`                        | Continue to next middleware      |
| `next(err)`                     | Pass error to error handler      |
| `res.send()`                    | End request                      |
| `res.json()`                    | End request with JSON            |
| `return res.status(...).send()` | Stop execution and send response |

---

# 15. Interview Answer

> **The `next()` function in Express is used inside middleware to pass control to the next middleware or route handler in the request-response cycle. Every middleware receives `req`, `res`, and `next` as arguments. If the middleware completes its task and wants processing to continue, it calls `next()`. If it encounters an error, it can call `next(err)` to delegate error handling. If the middleware sends a response using methods like `res.send()` or `res.json()`, it should not call `next()` afterward because the request has already been completed.**
