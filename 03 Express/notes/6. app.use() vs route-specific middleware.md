# `app.use()` vs Route-Specific Middleware in Express.js

> **Interview Definition:**
> Express allows middleware to be registered **globally using `app.use()`** or **for specific routes** using methods like `app.get()`, `app.post()`, or `router.get()`.
> Global middleware runs for every matching request, while route-specific middleware executes only for the routes where it is attached.

# 1. What is `app.use()`?

`app.use()` registers middleware.

It is commonly used for:

- Logging
- Authentication
- JSON Parsing
- Static Files
- CORS
- Error Handling

Example:

```js
app.use(express.json());
```

This middleware runs for matching requests before route handlers.

---

# 2. What is Route-specific Middleware?

Route middleware runs **only for one route or a selected group of routes**.

Example:

```js
app.get("/dashboard", authMiddleware, (req, res) => {
  res.send("Dashboard");
});
```

Only:

```text
GET /dashboard
```

uses `authMiddleware`.

---

# 3. Why Do We Need Both?

Imagine an application.

Some middleware should run for **every request**.

```text
Logger

↓

JSON Parser

↓

CORS
```

Some middleware should run **only for protected routes**.

```text
Authentication

↓

Authorization

↓

Admin Route
```

Using global middleware for everything would perform unnecessary work on public routes.

# 6. Global Middleware

Example:

```js
import express from "express";

const app = express();

function logger(req, res, next) {
  console.log(req.method, req.url);

  next();
}

app.use(logger);

app.get("/", (req, res) => {
  res.send("Home");
});

app.get("/about", (req, res) => {
  res.send("About");
});
```

Request:

```text
GET /

GET /about
```

Output:

```text
GET /

GET /about
```

The logger runs for both routes.

---

# 7. Route-specific Middleware

```js
function auth(req, res, next) {
  console.log("Authenticated");

  next();
}

app.get("/dashboard", auth, (req, res) => {
  res.send("Dashboard");
});

app.get("/", (req, res) => {
  res.send("Home");
});
```

Requests:

```text
GET /

↓

Home
```

```text
GET /dashboard

↓

Authentication

↓

Dashboard
```

The authentication middleware is not executed for `/`.

---

# 8. Path-specific Middleware

`app.use()` can also be limited to a path.

```js
app.use("/admin", authMiddleware);
```

Routes:

```text
/admin

/admin/users

/admin/products
```

All pass through:

```text
authMiddleware
```

Flow:

```text
/admin

↓

Authentication

↓

Admin Route
```

Requests outside `/admin` bypass this middleware.

---

# 9. Multiple Middleware

You can attach multiple middleware to a single route.

```js
app.get("/profile", logger, auth, validate, (req, res) => {
  res.send("Profile");
});
```

Execution:

```text
Request

↓

Logger

↓

Authentication

↓

Validation

↓

Controller

↓

Response
```

# 10. Middleware Execution Order

Order matters.

Example:

```js
app.use(first);

app.use(second);

app.get("/", handler);
```

Execution:

```text
first

↓

second

↓

handler
```

---

### Another Example

```js
app.use(logger);

app.get("/users", auth, controller);
```

Flow:

```text
Request

↓

Logger

↓

Authentication

↓

Controller

↓

Response
```

Global middleware executes before route middleware if registered first.

# 13. Best Practices

Use `app.use()` for:

- Logging
- CORS
- JSON parsing
- Static files
- Global error handling

Use route-specific middleware for:

- Authentication
- Authorization
- Validation
- Rate limiting (when only certain routes need it)
- Admin access

# 15. Common Interview Questions

### What is `app.use()`?

It registers middleware for the application. Middleware can apply globally or to a specific path prefix.

---

### Difference between `app.use()` and `app.get()` middleware?

`app.use()` registers middleware, while `app.get()` defines a handler for GET requests and can optionally include middleware for that route.

---

### Does `app.use()` run for every request?

If registered without a path (for example, `app.use(logger)`), it runs for every incoming request. If registered with a path (for example, `app.use("/admin", auth)`), it runs only for matching paths.

---

### Which executes first?

Middleware executes in the order it is registered.

---

### Why use route-specific middleware?

To apply logic only where needed, avoiding unnecessary processing on unrelated routes.

# 17. Interview Answer

> **`app.use()` is used to register middleware globally or for a specific path prefix. It is commonly used for cross-cutting concerns such as logging, JSON parsing, CORS, and serving static files. Route-specific middleware is attached directly to a route using methods like `app.get()` or `router.get()` and runs only for that route. Middleware is executed in the order it is registered, allowing Express applications to separate common functionality from route-specific logic while keeping the code modular and maintainable.**
