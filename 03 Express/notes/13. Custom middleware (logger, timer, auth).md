# Express.js Custom Middleware (Logger, Timer, Authentication)

> **Interview Definition:**
> **Custom middleware** is a middleware function written by the developer to perform application-specific tasks during the request-response cycle. It has access to the **Request (`req`)**, **Response (`res`)**, and **`next()`** function, allowing it to inspect, modify, or terminate requests before they reach the route handler.

# 1. What is Custom Middleware?

Unlike built-in middleware (`express.json()`) or third-party middleware (`cors`, `morgan`), **custom middleware is written by you**.

Example:

```text
Request

↓

Logger

↓

Authentication

↓

Validation

↓

Controller

↓

Response
```

Every middleware performs one specific task.

---

# 2. Why Do We Need Custom Middleware?

Imagine every route checks authentication.

Without middleware:

```js
app.get("/profile", (req, res) => {
  // Authentication
  // Logging
  // Validation
});

app.get("/orders", (req, res) => {
  // Authentication
  // Logging
  // Validation
});
```

The same logic is repeated.

With middleware:

```text
Request

↓

Logger

↓

Authentication

↓

Validation

↓

Route
```

Reusable and cleaner.

# 4. Middleware Syntax

```js
function middleware(req, res, next) {
  // Your logic

  next();
}
```

Arrow function:

```js
const middleware = (req, res, next) => {
  next();
};
```

# 5. Logger Middleware

Logs every request.

```js
function logger(req, res, next) {
  console.log("Method:", req.method);

  console.log("URL:", req.originalUrl);

  console.log("Time:", new Date().toISOString());

  next();
}
```

Register globally:

```js
app.use(logger);
```

Request:

```http
GET /users
```

Output:

```text
Method: GET
URL: /users
Time: 2026-07-04T12:30:15.123Z
```

---

### Flow

```text
Request

↓

Logger

↓

next()

↓

Route

↓

Response
```

# 6. Timer Middleware

Measure request execution time.

```js
function timer(req, res, next) {
  const start = Date.now();

  res.on("finish", () => {
    const duration = Date.now() - start;

    console.log(`Completed in ${duration} ms`);
  });

  next();
}
```

Register:

```js
app.use(timer);
```

Output:

```text
Completed in 18 ms
```

---

### Flow

```text
Request

↓

Start Timer

↓

Controller

↓

Response

↓

Finish Event

↓

Execution Time
```

# 7. Authentication Middleware

Protect private routes.

```js
function auth(req, res, next) {
  const token = req.headers.authorization;

  if (!token) {
    return res.status(401).json({
      message: "Unauthorized",
    });
  }

  next();
}
```

Use:

```js
app.get("/profile", auth, (req, res) => {
  res.send("Welcome");
});
```

Request:

```http
GET /profile
Authorization: Bearer abc123
```

Without token:

```json
{
  "message": "Unauthorized"
}
```

---

### Flow

```text
Request

↓

Authentication

↓

Token Exists?

 │

 ├── No

 │

 ▼

401 Unauthorized

 │

 └── Yes

      ▼

next()

      ▼

Controller
```

# 8. Modifying the Request

Middleware can add data to the request object.

```js
function auth(req, res, next) {
  req.user = {
    id: 1,

    name: "Nitish",

    role: "Admin",
  };

  next();
}
```

Controller:

```js
app.get("/profile", auth, (req, res) => {
  res.json(req.user);
});
```

Response:

```json
{
  "id": 1,
  "name": "Nitish",
  "role": "Admin"
}
```

This pattern is widely used after JWT or session authentication.

# 12. Organizing Middleware

Large projects keep middleware in its own folder.

```text
src/

├── middleware/

│   ├── logger.js

│   ├── auth.js

│   ├── timer.js

│   ├── validate.js

│   └── errorHandler.js
```

Example:

```js
import logger from "./middleware/logger.js";
import auth from "./middleware/auth.js";

app.use(logger);

app.get("/profile", auth, profileController);
```

# 13. Best Practices

✅ Keep middleware focused on one responsibility.

✅ Always call `next()` if processing should continue.

✅ Use `return res.status(...).json(...)` when ending the request.

✅ Keep authentication, validation, and logging separate.

✅ Store middleware in a dedicated folder.

# 14. Common Interview Questions

### What is custom middleware?

Middleware written by the developer for application-specific functionality.

---

### Why use custom middleware?

To avoid duplicating logic across routes and to separate concerns.

---

### Can middleware modify `req`?

Yes.

A common example is adding `req.user` after successful authentication.

---

### Can middleware stop a request?

Yes.

It can send a response such as:

```js
return res.status(401).json({
  message: "Unauthorized",
});
```

---

### Should middleware always call `next()`?

Only if it wants processing to continue. If it sends a response, it should not call `next()` afterward.

# 16. Interview Answer

> **Custom middleware in Express is a developer-defined function that executes during the request-response cycle. It receives the request object, response object, and the `next()` function. Custom middleware is commonly used for logging, authentication, authorization, validation, measuring request duration, and enriching the request object with additional data such as authenticated user information. Middleware promotes code reuse and separation of concerns by moving shared logic out of route handlers.**
