# Express.js Router Modules (`express.Router()`)

> **Interview Definition:**
> **`express.Router()`** is a mini Express application that allows you to group related routes into separate modules. It helps organize large applications by separating routes into different files, making the codebase modular, reusable, and easier to maintain.

# 1. What is `express.Router()`?

`express.Router()` creates a **mini Express application**.

```js
import express from "express";

const router = express.Router();
```

The router behaves like a smaller version of the main Express app.

It supports:

- `router.get()`
- `router.post()`
- `router.put()`
- `router.patch()`
- `router.delete()`
- `router.use()`
- `router.route()`

---

# Why is it called a Mini Application?

Both `app` and `router` can define routes and middleware.

```text
Express Application (app)

│

├── app.get()

├── app.post()

├── app.use()

└── app.listen()



Express Router (router)

│

├── router.get()

├── router.post()

├── router.use()

└── router.route()
```

Difference:

- `app` starts the server.
- `router` organizes routes.

# 2. Why Do We Need Router Modules?

Imagine a large project.

Without routers:

```text
index.js

↓

2000 Lines

↓

Users Routes

Products Routes

Orders Routes

```

Everything is inside one file.

Instead:

```text

├── users.js

├── products.js

├── auth.js

├── orders.js

└── payments.js
```

Each module contains only related routes.

# 4. Creating a Router

### routes/users.js

```js
import express from "express";

const router = express.Router();

router.get("/", (req, res) => {
  res.send("All Users");
});

router.get("/:id", (req, res) => {
  res.send(`User ${req.params.id}`);
});

export default router;
```

The router now manages all user-related routes.

---

# 5. Registering the Router

### app.js

```js
import express from "express";

import userRouter from "./routes/users.js";

const app = express();

app.use("/users", userRouter);

app.listen(3000);
```

Requests:

```text
GET /users

↓

All Users
```

```text
GET /users/10

↓

User 10
```

Flow:

```text
Request

↓

app.use("/users")

↓

userRouter

↓

Matching Route

↓

Response
```

# 6. Multiple Routers

```js
import userRouter from "./routes/users.js";

app.use("/products", productRouter);

app.use("/auth", authRouter);
```

Architecture

```text
Express App

│

├── /users
```

# 7. `app` vs `router`

| `app`                          | `router`                         |
| ------------------------------ | -------------------------------- |
| Main application               | Mini application                 |
| Created using `express()`      | Created using `express.Router()` |
| Starts server using `listen()` | Cannot start server              |
| Registers routers              | Contains related routes          |
| One per application            | Multiple routers allowed         |

# 8. Route Chaining with Router

Instead of:

```js
router.get("/users", getUsers);

router.post("/users", createUser);
```

Use:

```js
router
  .route("/")

  .get(getUsers)

  .post(createUser);
```

For a single resource:

```js
router
  .route("/:id")

  .get(getUser)

  .put(replaceUser)

  .patch(updateUser)

  .delete(deleteUser);
```

This is a common REST API pattern.

# 9. Router Middleware

Middleware can be attached only to a router.

```js
router.use((req, res, next) => {
  console.log("User Router");

  next();
});
```

Flow:

```text
/users

↓

Router Middleware

↓

User Route

↓

Response
```

The middleware only affects routes in this router.

---

# Route-specific Middleware

```js
function auth(req, res, next) {
  console.log("Authenticated");

  next();
}

router.get("/profile", auth, (req, res) => {
  res.send("Profile");
});
```

Each router imports controllers instead of containing business logic directly.

# Example

### routes/user.routes.js

```js
import express from "express";

import { getUsers, createUser } from "../controllers/user.controller.js";

const router = express.Router();

router
  .route("/")

  .get(getUsers)

  .post(createUser);

export default router;
```

---

# app.js

```js
import express from "express";

import userRouter from "./routes/user.routes.js";

const app = express();

app.use("/users", userRouter);
```

# 13. Best Practices

✅ One router per feature/module.

Examples:

```text
users

products

orders

payments

auth
```

✅ Keep business logic in controllers and services.

✅ Use `router.route()` for CRUD endpoints.

✅ Use router-level middleware for feature-specific concerns.

# 14. Common Interview Questions

### What is `express.Router()`?

A mini Express application used to organize related routes into separate modules.

---

### Why use routers?

To make applications modular, reusable, and easier to maintain.

---

### Can routers have middleware?

Yes.

Router-level middleware only affects routes within that router.

---

### Difference between `app` and `router`?

| App                | Router              |
| ------------------ | ------------------- |
| Entire application | Mini application    |
| Starts server      | Cannot start server |
| Registers routers  | Groups routes       |

---

### Can routers be nested?

Yes.

Routers can be mounted inside other routers using `router.use()` or `app.use()`.

# 16. Interview Answer

> **`express.Router()` is a feature in Express that creates a mini application for grouping related routes. Instead of defining all routes in a single file, developers can organize them into feature-based modules such as users, products, or authentication. Routers support route handlers, middleware, and route chaining, and are mounted into the main application using `app.use()`. This modular approach improves readability, scalability, maintainability, and code reuse in larger Express applications.**
