# Express.js Route Grouping and Prefixes

> **Interview Definition:**
> **Route Grouping** is the practice of organizing related routes into a single router, while a **Route Prefix** is a common URL segment added to all routes in that router using `app.use(prefix, router)`. This keeps applications modular, avoids repeating URL paths, and makes APIs easier to maintain.

# 1. What is Route Grouping?

Route grouping means placing related routes inside the same router.

Example:

Instead of:

```text
index.js

↓

Users

Products

Orders

Payments

Authentication
```

We create separate routers:

```text
routes/

├── users.routes.js

├── products.routes.js

├── orders.routes.js

├── auth.routes.js

└── payments.routes.js
```

Each router manages one feature.

---

# 2. What is a Route Prefix?

A **route prefix** is a common path added to every route inside a router.

Example:

```js
app.use("/users", userRouter);
```

If the router contains:

```js
router.get("/");
```

Actual URL:

```text
GET /users
```

If the router contains:

```js
router.get("/:id");
```

Actual URL:

```text
GET /users/10
```

The `/users` part is the **prefix**.

---

# 3. Why Do We Need Them?

Without prefixes:

```js
app.get("/users", ...);

app.get("/users/:id", ...);

app.post("/users", ...);

app.put("/users/:id", ...);

app.delete("/users/:id", ...);
```

The path `/users` is repeated many times.

With prefixes:

```js
app.use("/users", userRouter);
```

Inside the router:

```js
router.get("/");

router.get("/:id");

router.post("/");

router.put("/:id");

router.delete("/:id");
```

Cleaner and easier to maintain.

# 5. Without Route Grouping

Everything inside one file:

```js
app.get("/users", getUsers);

app.post("/users", createUser);

app.get("/products", getProducts);

app.post("/products", createProduct);

app.get("/orders", getOrders);

app.post("/orders", createOrder);
```

Problems:

- Repeated paths
- Large files
- Difficult maintenance

# 6. Using Route Grouping

### users.routes.js

```js
import express from "express";

const router = express.Router();

router.get("/", (req, res) => {
  res.send("All Users");
});

router.post("/", (req, res) => {
  res.send("Create User");
});

router.get("/:id", (req, res) => {
  res.send(`User ${req.params.id}`);
});

export default router;
```

---

### app.js

```js
import express from "express";
import userRouter from "./routes/users.routes.js";

const app = express();

app.use("/users", userRouter);
```

Requests:

```text
GET /users

GET /users/10

POST /users
```

# 7. Route Prefixes

Example:

```js
app.use("/products", productRouter);
```

Inside the router:

```js
router.get("/");

router.post("/");

router.get("/:id");
```

Generated URLs:

```text
GET /products

POST /products

GET /products/5
```

The router doesn't know about `/products`.

The prefix is added by:

```js
app.use("/products", productRouter);
```

---

# 8. Multiple Routers

```js
app.use("/users", userRouter);

app.use("/products", productRouter);

app.use("/orders", orderRouter);

app.use("/payments", paymentRouter);

app.use("/auth", authRouter);
```

Architecture:

```text
Express App

│

├── /users

├── /products

├── /orders

├── /payments

└── /auth
```

Each feature has its own router.

---

# 9. API Versioning

Route prefixes are commonly used for API versioning.

```js
app.use("/api/v1", apiV1Router);

app.use("/api/v2", apiV2Router);
```

Requests:

```text
GET /api/v1/users

GET /api/v2/users
```

Benefits:

- Support multiple API versions
- Backward compatibility
- Easier migrations

---

# 10. Nested Route Prefixes

Example:

```js
app.use("/api", apiRouter);
```

Inside `apiRouter`:

```js
router.use("/users", userRouter);

router.use("/orders", orderRouter);
```

Inside `userRouter`:

```js
router.get("/");
```

Actual URL:

```text
GET /api/users
```

Flow:

```text
Request

↓

Express App

↓

API Router

↓

User Router

↓

Controller

↓

Response
```

# 12. Complete Example

### app.js

```js
import express from "express";

import userRouter from "./routes/users.routes.js";
import productRouter from "./routes/products.routes.js";

const app = express();

app.use("/api/users", userRouter);

app.use("/api/products", productRouter);

app.listen(3000);
```

---

### users.routes.js

```js
import express from "express";

const router = express.Router();

router.get("/", (req, res) => {
  res.send("Users");
});

router.get("/:id", (req, res) => {
  res.send(`User ${req.params.id}`);
});

export default router;
```

Requests:

```text
GET /api/users

GET /api/users/5
```

# 13. Best Practices

✅ Group routes by feature.

Examples:

- Users
- Products
- Orders
- Authentication

✅ Use meaningful prefixes.

```text
/api/users

/api/products

/api/orders
```

✅ Keep routers small.

✅ Keep controllers separate from routers.

✅ Use API version prefixes for public APIs.

# 14. Common Interview Questions

### What is Route Grouping?

Organizing related routes into the same router module.

---

### What is a Route Prefix?

A common URL path added when mounting a router using `app.use(prefix, router)`.

---

### Why use prefixes?

To avoid repeating paths and organize APIs.

---

### Can routers have different prefixes?

Yes.

```js
app.use("/users", userRouter);

app.use("/admin/users", adminUserRouter);
```

---

### Why use `/api/v1`?

To version APIs and support backward compatibility while new versions are introduced.

# 16. Interview Answer

> **Route grouping in Express.js is the practice of organizing related endpoints into separate router modules using `express.Router()`. Route prefixes are common URL segments added when mounting a router with `app.use(prefix, router)`. This approach eliminates repeated path definitions, improves modularity, simplifies maintenance, and supports scalable API designs. Prefixes are also widely used for API versioning, such as `/api/v1`, allowing multiple API versions to coexist while maintaining backward compatibility.**
