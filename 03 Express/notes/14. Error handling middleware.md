# Express.js Error Handling Middleware (404 & Global Error Handler)

> **Interview Definition:**
> **Error Handling Middleware** is a special type of middleware in Express that catches and processes errors occurring during the request-response cycle. It has **four parameters** (`err, req, res, next`) and is typically registered **after all routes**. A **404 handler** is a separate middleware that handles requests for routes that do not exist.

# 1. What is Error Handling Middleware?

Express provides a special middleware for handling errors.

Unlike normal middleware:

```js
(req, res, next);
```

Error middleware has **four arguments**:

```js
(err, req, res, next);
```

The first parameter (`err`) tells Express this is an error-handling middleware.

---

# 2. Why Do We Need It?

Without centralized error handling:

```text
Request

↓

Controller

↓

Error

↓

Application Crashes
```

With error middleware:

```text
Request

↓

Controller

↓

Error

↓

Global Error Handler

↓

JSON Response
```

Instead of crashing or returning inconsistent responses, the application returns a structured error.

# 4. 404 Handler

A 404 handler catches requests that don't match any route.

```js
app.use((req, res) => {
  res.status(404).json({
    success: false,

    message: "Route Not Found",
  });
});
```

Request:

```http
GET /random
```

Response:

```json
{
  "success": false,
  "message": "Route Not Found"
}
```

---

### Why Does It Work?

Express checks routes from top to bottom.

```text
GET /users

↓

No Match

↓

GET /products

↓

No Match

↓

404 Middleware

↓

Response
```

The 404 middleware must be **after all routes**.

---

# 5. Global Error Handler

Create a global error middleware.

```js
app.use((err, req, res, next) => {
  console.error(err);

  res.status(500).json({
    success: false,

    message: err.message || "Internal Server Error",
  });
});
```

Notice the four parameters:

```js
(err, req, res, next);
```

---

# 6. Using `next(err)`

When something goes wrong:

```js
app.get("/users", (req, res, next) => {
  try {
    throw new Error("Database Error");
  } catch (err) {
    next(err);
  }
});
```

Flow:

```text
Controller

↓

next(err)

↓

Error Middleware

↓

Response
```

# 8. Synchronous vs Asynchronous Errors

### Synchronous Error

```js
app.get("/sync", (req, res) => {
  throw new Error("Sync Error");
});
```

Express automatically forwards synchronous errors to the error handler.

---

### Asynchronous Error

```js
app.get("/async", async (req, res, next) => {
  try {
    throw new Error("Async Error");
  } catch (err) {
    next(err);
  }
});
```

For asynchronous code, pass the error to `next(err)` (or use a helper library/pattern that forwards rejected promises automatically).

# 9. Custom Error Example

Authentication middleware:

```js
function auth(req, res, next) {
  if (!req.headers.authorization) {
    return next(new Error("Unauthorized"));
  }

  next();
}
```

Global handler:

```js
app.use((err, req, res, next) => {
  res.status(401).json({
    success: false,

    message: err.message,
  });
});
```

Response:

```json
{
  "success": false,
  "message": "Unauthorized"
}
```



# 11. Best Practices

✅ Place the 404 handler after all routes.

✅ Register the global error handler last.

✅ Return consistent JSON error responses.

✅ Log errors for debugging.

✅ Use meaningful HTTP status codes.

---

# 12. Common Mistakes

### Error Middleware Before Routes

```js
app.use(errorHandler);

app.get("/", controller);
```

Incorrect order.

---

### Forgetting `next(err)`

```js
catch (err) {

    // Nothing happens

}
```

The request may hang or the error may never reach the global handler.

---

### Returning HTML for APIs

```html
<h1>Error</h1>
```

Prefer JSON for REST APIs.

# 13. Common Interview Questions

### What makes error middleware different?

It has four parameters:

```js
(err, req, res, next);
```

---

### Why is the 404 handler separate?

A 404 is **not** an application error. It simply means no route matched the request.

---

### Where should the error handler be registered?

After all middleware and routes.

---

### What does `next(err)` do?

It skips normal middleware and forwards control to the nearest error-handling middleware.

---

### Can Express catch every asynchronous error automatically?

No. Errors in asynchronous code should be forwarded using `next(err)` or another mechanism that passes rejected promises to the error handler.

# 15. Interview Answer

> **Express uses a special error-handling middleware to process errors that occur during the request-response cycle. Unlike normal middleware, it has four parameters: `(err, req, res, next)`. Errors are forwarded to this middleware using `next(err)` or by throwing synchronous errors. A separate 404 middleware handles requests that do not match any route. In a production application, the 404 handler is registered after all routes, and the global error-handling middleware is registered last to provide consistent logging and structured error responses.**
