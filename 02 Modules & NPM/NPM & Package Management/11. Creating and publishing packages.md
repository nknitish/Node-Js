# Creating and Publishing npm Packages

> **Interview Definition:**
> An **npm package** is reusable code that can be published to the npm registry and installed by other developers. Publishing a package involves creating a project, configuring `package.json`, exporting your code, testing it locally, and publishing it with npm.

# 1. What is an npm Package?

An npm package is reusable JavaScript or TypeScript code that can be installed using npm.

Examples:

```text id="l7t4k6"
express

react

axios

lodash

chalk
```

Instead of copying code between projects, you publish it once and install it anywhere.

# 7. package.json

```json id="9hjlwm"
{
  "name": "my-utils-package",
  "version": "1.0.0",
  "description": "Utility functions",
  "type": "module",
  "main": "index.js",
  "keywords": ["utility", "javascript"],
  "author": "Your Name",
  "license": "MIT"
}
```

---

# Important Fields

## name

Package name.

```json id="ix4gsi"
{
  "name": "my-utils-package"
}
```

Must be unique on the npm registry (unless using a scope).

---

## version

```json id="vcic4r"
{
  "version": "1.0.0"
}
```

Uses Semantic Versioning.

---

## main

Entry point.

```json id="pwjlwm"
{
  "main": "index.js"
}
```

---

## type

```json id="oqmdzt"
{
  "type": "module"
}
```

Enables ES Modules.

---

## files

Controls which files are included when publishing.

```json id="3mjlwm"
{
  "files": ["index.js", "dist"]
}
```

This helps avoid publishing unnecessary files such as tests or local configuration.

---

## exports

Defines the public API of your package.

```json id="j2fd9d"
{
  "exports": {
    ".": "./index.js"
  }
}
```

# 8. Test the Package Locally

### Option 1: npm link

Create a global symlink:

```bash id="rgij8v"
npm link
```

In another project:

```bash id="pdjlwm"
npm link my-utils-package
```

Use it:

```js id="njlwm0"
import { add } from "my-utils-package";

console.log(add(2, 3));
```

---

### Option 2: Local File Install

```bash id="8jlwm3"
npm install ../my-utils
```

Useful during development.

# 10. Update Your Package

Make changes:

```js id="2jlwm7"
export function multiply(a, b) {
  return a * b;
}
```

Update the version:

```bash id="jlwm8"
npm version patch
```

Possible version updates:

```bash id="jlwm9"
npm version patch

npm version minor

npm version major
```

Publish again:

```bash id="jlwm10"
npm publish
```

# 11. Scoped Packages

Personal or organization packages often use scopes.

Example:

```json id="jlwm11"
{
  "name": "@nitish/utils"
}
```

Publish:

```bash id="jlwm12"
npm publish --access public
```

Install:

```bash id="jlwm13"
npm install @nitish/utils
```

# 13. Best Practices

- Write a good README.
- Include a license.
- Use Semantic Versioning.
- Export only the public API.
- Use the `files` field or `.npmignore`.
- Add tests.
- Keep dependencies minimal.
- Avoid publishing secrets or configuration files.

# 14. Common Interview Questions

### What is an npm package?

A reusable piece of code that can be published to the npm registry and installed into other projects.

---

### What is required before publishing?

- Valid `package.json`
- Unique package name
- npm account
- Logged in with `npm login`

---

### What does `npm publish` do?

It uploads the package to the npm registry, making it available for installation by others.

---

### Why use `npm link`?

To test a package locally before publishing by creating a symlink between your package and another project.

---

### What is a scoped package?

A package whose name includes a scope, such as `@company/package`, commonly used by individuals and organizations.

# Interview Answer

> **Creating an npm package involves organizing reusable code, initializing a project with `package.json`, defining an entry point, and exporting the public API. Before publishing, the package should be tested locally using `npm link` or a local file install. After logging in with `npm login`, the package can be published using `npm publish`. Future updates follow Semantic Versioning and are released by updating the version and publishing again. Fields such as `files`, `exports`, and `main` help control what consumers can access and what gets included in the published package.**
