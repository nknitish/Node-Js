# Semantic Versioning (SemVer) in Node.js

> **Interview Definition:**
> **Semantic Versioning (SemVer)** is a versioning standard used by npm to manage package versions. It follows the format **MAJOR.MINOR.PATCH** and uses symbols like **`^`**, **`~`**, and exact versions to control which package updates are allowed.

# 1. What is Semantic Versioning?

Every npm package has a version.

Example:

```text
18.2.0
```

This follows the format:

```text
MAJOR.MINOR.PATCH

18 . 2 . 0
```

---

# 2. Why Do We Need It?

Suppose you're using Express.

```json
{
  "dependencies": {
    "express": "^5.0.0"
  }
}
```

A new version is released.

Without version rules:

```text
Your App

↓

Random Version Installed

↓

Possible Breaking Changes
```

SemVer helps control **which updates are allowed**.

---

# 3. Version Structure

```text
MAJOR.MINOR.PATCH

1 . 4 . 2
```

### MAJOR

Breaking changes.

Example:

```text
1.0.0

↓

2.0.0
```

API changes that may require code updates.

---

### MINOR

New features.

```text
1.4.0

↓

1.5.0
```

Backward compatible.

---

### PATCH

Bug fixes.

```text
1.4.2

↓

1.4.3
```

No API changes.

# 4. Exact Version

Example:

```json
{
  "dependencies": {
    "express": "5.0.1"
  }
}
```

npm installs:

```text
Only

5.0.1
```

It will **not** automatically install:

```text
5.0.2 ❌

5.1.0 ❌

6.0.0 ❌
```

### When to use

- Production systems requiring strict control
- Internal packages
- Reproducible environments

---

# 5. Caret (`^`)

Most common version range.

Example:

```json
{
  "dependencies": {
    "express": "^5.0.1"
  }
}
```

Allows:

```text
5.0.2 ✅

5.1.0 ✅

5.9.8 ✅
```

Does **not** allow:

```text
6.0.0 ❌
```

Visual

```text
^5.0.1

5.x.x

Allowed

6.0.0

Not Allowed
```

### Rule

Allow:

- Minor updates
- Patch updates

Block:

- Major updates

---

# 6. Tilde (`~`)

More restrictive.

Example:

```json
{
  "dependencies": {
    "express": "~5.0.1"
  }
}
```

Allows:

```text
5.0.2 ✅

5.0.3 ✅

5.0.9 ✅
```

Does **not** allow:

```text
5.1.0 ❌

6.0.0 ❌
```

Visual

```text
~5.0.1

5.0.x

Allowed

5.1.0

Not Allowed
```

### Rule

Allow:

- Patch updates only

Block:

- Minor updates
- Major updates

# Real-world Example

Suppose:

```text
Current Version

4.3.2
```

New versions:

```text
4.3.3

4.4.0

5.0.0
```

| Version Specifier | Installed Version                                    |
| ----------------- | ---------------------------------------------------- |
| `"4.3.2"`         | 4.3.2 only                                           |
| `"~4.3.2"`        | 4.3.3                                                |
| `"^4.3.2"`        | 4.4.0                                                |
| `"*"`             | Latest available (not recommended for most projects) |

# Best Practices

### Applications

Use:

```json
{
  "dependencies": {
    "express": "^5.0.0"
  }
}
```

This is the most common choice because it receives backward-compatible updates.

---

### Libraries

Test carefully before widening version ranges, since your package will be used by other projects.

---

### CI/CD

Commit:

```text
package-lock.json
```

This locks the exact versions installed, even if `package.json` uses `^` or `~`.

# Common Interview Questions

### What is Semantic Versioning?

A versioning system using the format **MAJOR.MINOR.PATCH** to communicate the impact of software changes.

---

### Difference between `^` and `~`?

| `^`                   | `~`                |
| --------------------- | ------------------ |
| Minor + Patch updates | Patch updates only |

---

### Difference between `^` and Exact Version?

| `^5.0.0`                                         | `"5.0.0"`                       |
| ------------------------------------------------ | ------------------------------- |
| Updates to newer compatible minor/patch versions | Always installs exactly `5.0.0` |

---

### Why doesn't `^5.0.0` install `6.0.0`?

Because a major version may contain breaking changes, and the caret range is designed to avoid automatically introducing them.

---

### Why doesn't everyone use exact versions?

Exact versions reduce automatic updates. Many projects prefer `^` during development to receive compatible bug fixes and features, while `package-lock.json` ensures consistent installations.

# Quick Revision

| Symbol    | Allows                                      |
| --------- | ------------------------------------------- |
| `"1.2.3"` | Exact version only                          |
| `~1.2.3`  | Patch updates                               |
| `^1.2.3`  | Minor + Patch updates                       |
| `*`       | Any version (generally avoid in production) |

# Interview Answer

> **Semantic Versioning (SemVer) is a standard versioning scheme that uses the format MAJOR.MINOR.PATCH. Major versions introduce breaking changes, minor versions add backward-compatible features, and patch versions contain backward-compatible bug fixes. In npm, an exact version installs only the specified version, `~` allows patch updates within the same minor version, and `^` allows both minor and patch updates within the same major version. Most Node.js applications use `^` in `package.json` together with `package-lock.json` to receive compatible updates while ensuring reproducible installations.**
