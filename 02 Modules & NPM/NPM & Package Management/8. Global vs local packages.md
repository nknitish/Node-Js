# Global vs Local Packages in Node.js

> **Interview Definition:**
> In Node.js, packages can be installed **locally** (inside a project) or **globally** (available system-wide). Local packages are used by a specific project, while global packages provide command-line tools that can be used from any terminal location.

# 1. What are npm Packages?

Node.js applications often use external packages from npm.

Example:

```bash
npm install express
```

Packages can be installed in **two ways**:

```text
1. Local

2. Global
```

---

# 2. Local Packages

A **local package** is installed inside a project.

Command:

```bash
npm install express
```

Project structure:

```text
my-project/
│
├── node_modules/
│   └── express/
│
├── package.json
└── package-lock.json
```

Only this project can use the installed package.

---

# Example

```bash
npm install axios
```

Result:

```text
my-project/

↓

node_modules/

↓

axios
```

---

# Why Local Packages?

Every project can have different versions.

Example:

```text
Project A

↓

React 18

-------------------

Project B

↓

React 19
```

No conflicts occur because each project has its own `node_modules`.

---

# 3. Global Packages

Global packages are installed once on your computer.

Command:

```bash
npm install -g nodemon
```

Now you can run:

```bash
nodemon app.js
```

from any directory.

---

# How Global Installation Works

```text
npm install -g nodemon

↓

Global npm Directory

↓

PATH Environment Variable

↓

Available Everywhere
```

# 6. Local vs Global

| Local Package                | Global Package                           |
| ---------------------------- | ---------------------------------------- |
| Installed per project        | Installed once on the computer           |
| Stored in `node_modules`     | Stored in npm's global directory         |
| Listed in `package.json`     | Not listed in a project's `package.json` |
| Version isolated per project | Shared across the system                 |
| Used by application code     | Typically used as CLI tools              |

# 8. Running Packages

## Local Package

Usually through npm scripts:

```json
{
  "scripts": {
    "dev": "vite"
  }
}
```

Run:

```bash
npm run dev
```

npm automatically finds `vite` inside `node_modules/.bin`.

You can also run:

```bash
npx vite
```

without installing it globally.

---

## Global Package

```bash
nodemon app.js
```

Works from any directory because the executable is on your system `PATH`.

# 9. Where Are They Installed?

## Local

```text
project/

↓

node_modules/
```

---

## Global

Windows (example)

```text
C:\Users\<user>\AppData\Roaming\npm
```

Linux/macOS (location varies by installation)

```text
/usr/local/lib/node_modules
```

You can check the location with:

```bash
npm root -g
```

# 11. Why Prefer Local Packages?

Suppose:

```text
Developer A

↓

TypeScript 5.8

---------------------

Developer B

↓

TypeScript 5.6
```

If TypeScript is installed locally in the project:

```text
Project

↓

node_modules

↓

Same Version

↓

Everyone Builds Successfully
```

This improves consistency across the team.

---

# 13. `npx`

Instead of:

```bash
npm install -g create-vite
```

Use:

```bash
npx create-vite
```

Benefits:

- Downloads the package if needed
- Runs it
- Doesn't require a permanent global installation

# 14. Common Interview Questions

### What is the difference between local and global packages?

Local packages belong to a specific project, while global packages are installed once and are typically available as CLI commands system-wide.

---

### Where are local packages installed?

Inside the project's `node_modules` directory.

---

### Where are global packages installed?

In npm's global installation directory, which can be viewed using:

```bash
npm root -g
```

---

### Why shouldn't Express be installed globally?

Because each project may require a different version of Express, and application dependencies should be tracked in `package.json`.

---

### Why use `npx` instead of global installation?

`npx` lets you run CLI tools without permanently installing them globally, helping avoid version conflicts and reducing global package clutter.

| Tracked in `package.json` | ✅                         | ❌                   |
| Typical use               | Runtime/build dependencies | CLI tools            |

# Interview Answer

> **Local packages are installed inside a project's `node_modules` directory and are used only by that project. They are recorded in `package.json`, allowing different projects to use different package versions. Global packages are installed once on the system and are primarily used as command-line tools, such as `nodemon` or `pnpm`. In modern development, application dependencies should generally be installed locally, while tools that need to be available from any terminal may be installed globally or run using `npx` when appropriate.**
