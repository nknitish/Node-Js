# `dependencies` vs `devDependencies` in Node.js

> **Interview Definition:**
> In a Node.js project, **`dependencies`** are packages required for the application to run in production, while **`devDependencies`** are packages used only during development, testing, linting, or building the project.

# 1. What are Dependencies?

Dependencies are external packages that your application needs.

Example:

```text
Node.js App
        │
        ▼
Uses Express
        │
        ▼
Express Package
```

Without Express, your server cannot run.

---

# 2. Why Do We Need Two Types?

Not every package is needed in production.

Example:

```text
During Development
│
├── ESLint
├── Prettier
├── Jest
├── Nodemon
└── TypeScript

↓

Production Server

↓

Only Express
```

Keeping development tools separate reduces production installs and keeps deployments smaller.

# 4. `dependencies`

These packages are required **when your application is running**.

Install:

```bash
npm install express
```

This updates:

```json
{
  "dependencies": {
    "express": "^5.0.0"
  }
}
```

### Common Examples

| Package      | Purpose                    |
| ------------ | -------------------------- |
| express      | Web server                 |
| mongoose     | MongoDB ODM                |
| axios        | HTTP client                |
| dotenv       | Load environment variables |
| jsonwebtoken | JWT authentication         |
| bcrypt       | Password hashing           |
| socket.io    | Real-time communication    |

### Architecture

```text
Client
      │
      ▼
Node.js App
      │
      ▼
Express
      │
      ▼
Database
```

If Express is missing, the application cannot start.

---

# 5. `devDependencies`

These packages are needed only while developing the project.

Install:

```bash
npm install -D eslint
```

or

```bash
npm install --save-dev eslint
```

This updates:

```json
{
  "devDependencies": {
    "eslint": "^9.0.0"
  }
}
```

### Common Examples

| Package    | Purpose                         |
| ---------- | ------------------------------- |
| eslint     | Code linting                    |
| prettier   | Code formatting                 |
| jest       | Unit testing                    |
| vitest     | Unit testing                    |
| nodemon    | Auto-restart during development |
| typescript | Type checking and compilation   |
| webpack    | Bundling                        |
| vite       | Development/build tooling       |

These tools help developers but are typically not needed to run the deployed application.

# 6. Installation Commands

## Install a Production Dependency

```bash
npm install express
```

Saved in:

```json
"dependencies"
```

---

## Install a Development Dependency

```bash
npm install -D jest
```

Saved in:

```json
"devDependencies"
```

# 10. Production Install

To install only production dependencies:

```bash
npm install --omit=dev
```

This skips `devDependencies`.

This is useful in some production environments and Docker builds.

---

# 11. Common Interview Questions

### What is the difference between `dependencies` and `devDependencies`?

`dependencies` are required for the application to run, while `devDependencies` are used during development, testing, and building.

---

### Is Express a dependency or a devDependency?

A dependency, because the server requires it at runtime.

---

### Is Jest a dependency or a devDependency?

A devDependency, because it is used for testing during development.

---

### Is TypeScript always a devDependency?

Usually yes.

However, some libraries or build pipelines may have specific requirements, but in most applications it belongs in `devDependencies`.

---

### Can an application run without `devDependencies`?

Yes, provided all required runtime packages are listed under `dependencies` and the application has already been built if necessary.

# Interview Answer

> **`dependencies` contain packages that are required for the application to run in production, such as Express, Axios, or Mongoose. `devDependencies` contain packages that assist during development, including testing frameworks, linters, formatters, and build tools like Jest, ESLint, Prettier, and TypeScript. Separating them keeps production deployments focused on runtime requirements while allowing developers to use additional tooling locally.**
