# NPX in Node.js

> **Interview Definition:**
> **`npx`** (Node Package Execute) is a command-line tool that comes with npm. It allows you to execute npm packages **without permanently installing them globally**. It can also run locally installed package binaries from your project's `node_modules/.bin` directory.

# 1. What is NPX?

`npx` is a package runner.

It allows you to:

- Run locally installed packages
- Run packages without installing them globally
- Execute one-time CLI tools
- Run a specific package version

It comes bundled with modern versions of npm.

---

# 2. Why Do We Need NPX?

Before `npx`:

```bash
npm install -g create-react-app

create-react-app my-app
```

Problems:

- Global installation required
- Old global versions could remain installed
- Version conflicts

With `npx`:

```bash
npx create-react-app my-app
```

The tool is downloaded (if needed), executed, and you don't have to keep it installed globally.

# 3. How NPX Works

```text
User

↓

npx vite

↓

Check node_modules/.bin

↓

Package Found?

↓

Yes → Run Local Version

↓

No

↓

Download Temporary Package

↓

Execute

↓

Cleanup (when appropriate)
```

# 4. Running Local Packages

Suppose you install ESLint locally.

```bash
npm install -D eslint
```

Project structure:

```text
my-project/
│
├── node_modules/
│   └── .bin/
│       └── eslint
│
└── package.json
```

Run it:

```bash
npx eslint .
```

No global installation required.

---

# 5. Running Packages Without Installing

Example:

```bash
npx cowsay "Hello Nitish"
```

Output:

```text
 ________________
< Hello Nitish >
 ----------------
        \   ^__^
         \  (oo)\_______
            (__)\       )\/\
                ||----w |
                ||     ||
```

The package can be executed without adding it as a project dependency or installing it globally.

# 8. npm vs npx

| npm                                                | npx                        |
| -------------------------------------------------- | -------------------------- |
| Installs packages                                  | Executes packages          |
| Adds dependencies to the project (when installing) | Runs package binaries      |
| Used for dependency management                     | Used for running CLI tools |

# 12. Best Practices

Use `npx` for:

- Project generators
- One-time scripts
- Local CLI tools
- Testing a specific package version

Prefer npm scripts for commands you run regularly within a project.

# 13. Common Interview Questions

### What is `npx`?

A package runner that executes npm package binaries without requiring permanent global installation.

---

### Difference between `npm` and `npx`?

| npm                  | npx               |
| -------------------- | ----------------- |
| Installs packages    | Executes packages |
| Manages dependencies | Runs CLI commands |

---

### Why use `npx` instead of global installation?

It avoids unnecessary global packages, reduces version conflicts, and makes it easy to run the latest or project-local version of a CLI tool.

---

### Does `npx` always download packages?

No.

It first checks for a local executable in `node_modules/.bin`. If none exists, it can download the package temporarily (or use a cached copy) and execute it.

---

### Can `npx` run locally installed packages?

Yes.

For example:

```bash
npx eslint .
```

runs the local project version of ESLint.

# Interview Answer

> **`npx` is a package runner that comes with npm. It is used to execute package binaries without requiring permanent global installation. When a command is run, `npx` first looks for a matching executable in the project's `node_modules/.bin` directory. If it isn't found, `npx` can download the package temporarily, execute it, and then exit. It is commonly used for project generators like `create-vite`, running local development tools such as ESLint and Prettier, and testing specific package versions without installing them globally.**
