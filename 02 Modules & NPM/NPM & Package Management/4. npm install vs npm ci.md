# `npm install` vs `npm ci`

> **Interview Definition:**
> Both **`npm install`** and **`npm ci`** install project dependencies, but they are designed for different purposes. `npm install` is primarily used during development and can update the dependency tree, while `npm ci` performs a clean, deterministic installation based strictly on `package-lock.json`, making it ideal for CI/CD pipelines.

# 1. Introduction

Suppose your project contains:

```text
project/
│
├── package.json
├── package-lock.json
└── node_modules/
```

To install dependencies, npm provides two commands:

```bash
npm install
```

and

```bash
npm ci
```

Although both install packages, they behave differently.

---

# 2. `npm install`

`npm install` is the command most developers use during day-to-day development.

Example:

```bash
npm install
```

### What happens internally?

```text
Read package.json
        │
        ▼
Read package-lock.json (if present)
        │
        ▼
Resolve Dependencies
        │
        ▼
Install Packages
        │
        ▼
Update package-lock.json (if needed)
```

It can:

- Install new dependencies
- Update the lock file
- Create `node_modules`
- Add packages

---

## Installing a New Package

```bash
npm install express
```

This updates:

```text
package.json

↓

package-lock.json

↓

node_modules
```

---

# 3. `npm ci`

`ci` stands for **Continuous Integration**.

Example:

```bash
npm ci
```

### What happens internally?

```text
Delete node_modules
        │
        ▼
Read package-lock.json
        │
        ▼
Install Exact Versions
        │
        ▼
Done
```

Unlike `npm install`:

- It never updates `package-lock.json`
- It requires a valid lock file
- It performs a clean installation
- It is optimized for speed and consistency

# 5. Key Differences

| Feature                               | `npm install`                   | `npm ci`  |
| ------------------------------------- | ------------------------------- | --------- |
| Reads `package.json`                  | ✅                              | ✅        |
| Uses `package-lock.json`              | ✅                              | ✅        |
| Updates `package-lock.json`           | ✅ If needed                    | ❌ Never  |
| Deletes existing `node_modules` first | ❌                              | ✅        |
| Installs exact locked versions        | Usually (when lock file exists) | ✅ Always |
| Faster                                | ❌                              | ✅        |
| Best for                              | Development                     | CI/CD     |

# 6. Real-world Example

Suppose:

```json
{
  "dependencies": {
    "express": "^5.0.0"
  }
}
```

`package-lock.json`

```text
express 5.0.1
```

### `npm install`

May update the lock file if dependencies change.

### `npm ci`

Always installs:

```text

```

Exactly as recorded.

# 9. Common Errors

### Error

```text
package-lock.json is missing
```

Cause:

`npm ci` requires a lock file.

Solution:

```bash
npm install
```

to generate `package-lock.json`, then use:

```bash
npm ci
```

---

### Error

```text
package.json and package-lock.json are out of sync
```

Cause:

The dependency definitions don't match.

Fix:

```bash
npm install
```

Commit the updated lock file, then rerun:

```bash
npm ci
```

# Common Interview Questions

### What is `npm ci`?

A command that performs a clean, deterministic installation using the exact versions specified in `package-lock.json`.

---

### Why is `npm ci` faster?

Because it installs the locked dependency tree directly instead of resolving and potentially updating dependency versions.

---

### Can `npm ci` install a new package?

No.

Use:

```bash
npm install package-name
```

to add new dependencies.

---

### Which command should be used in CI/CD?

```bash
npm ci
```

---

### Does `npm ci` update `package-lock.json`?

No.

# Interview Answer

> **`npm install` is the standard command used during development to install dependencies, add new packages, and update the dependency tree when necessary. It reads `package.json`, uses `package-lock.json` if available, and may update the lock file. In contrast, `npm ci` is designed for Continuous Integration and production builds. It requires a valid `package-lock.json`, deletes the existing `node_modules` directory, and installs the exact locked dependency versions without modifying the lock file. This makes builds faster, deterministic, and consistent across different environments.**
