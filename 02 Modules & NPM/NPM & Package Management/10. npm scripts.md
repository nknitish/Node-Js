# NPM Scripts in Node.js

> **Interview Definition:**
> **NPM Scripts** are custom commands defined inside the `scripts` section of `package.json`. They allow developers to automate common tasks such as starting the application, running tests, linting code, building projects, formatting files, and executing custom scripts.

# 1. What are NPM Scripts?

NPM Scripts are commands stored inside the **`scripts`** section of `package.json`.

Example:

```json
{
  "scripts": {
    "start": "node index.js"
  }
}
```

Run:

```bash
npm start
```

Instead of:

```bash
node index.js
```

---

# 2. Why Do We Need Them?

Without npm scripts:

```text
Developer

↓

node server.js

↓

eslint .

↓

jest

↓

webpack

↓

prettier
```

You must remember every command.

With npm scripts:

```text
Developer

↓

npm run dev

↓

npm test

↓

npm run build
```

Simple, consistent, and easier for teams.


Custom scripts require `run`.

# Running Local Packages

Suppose ESLint is installed locally.

```bash
npm install -D eslint
```

Script:

```json
{
  "scripts": {
    "lint": "eslint ."
  }
}
```

Run:

```bash
npm run lint
```

NPM automatically executes:

```text
node_modules/.bin/eslint
```

No global installation required.

---

# 8. Script Chaining

Run multiple commands.

```json
{
  "scripts": {
    "build": "webpack",
    "test": "jest",
    "deploy": "npm run build && npm test"
  }
}
```

Run:

```bash
npm run deploy
```

Flow:

```text
Build

↓

Tests

↓

Done
```

# Running Scripts in Parallel

Example (requires a suitable tool such as `concurrently`):

```json
{
  "scripts": {
    "dev": "concurrently \"npm:start\" \"npm:test\""
  }
}
```

Useful for:

- Frontend + Backend
- Multiple services
- Watch mode

# 9. Environment Variables

Example:

```json
{
  "scripts": {
    "start": "NODE_ENV=production node index.js"
  }
}
```

> **Note:** On Windows, this syntax differs. Many projects use packages like `cross-env` to write cross-platform scripts.

Inside Node:

```js
console.log(process.env.NODE_ENV);
```

Output:

```text
production
```

# 10. Passing Arguments

Script:

```json
{
  "scripts": {
    "lint": "eslint"
  }
}
```

Run:

```bash
npm run lint -- src
```

NPM forwards everything after `--` to the underlying command.

Equivalent to:

```bash
eslint src
```

# 13. Best Practices

- Use descriptive script names.
- Keep scripts simple.
- Prefer local package binaries.
- Use npm scripts instead of relying on globally installed tools.
- Document uncommon scripts in your README.

# 14. Common Interview Questions

### What are npm scripts?

Custom commands defined in the `scripts` section of `package.json`.

---

### Why use npm scripts?

To automate common development tasks and provide a consistent way for all developers to run project commands.

---

### Why does `npm run lint` work without globally installing ESLint?

Because npm automatically adds `node_modules/.bin` to the PATH while running scripts.

---

### Difference between `npm start` and `npm run dev`?

| `npm start`           | `npm run dev`  |
| --------------------- | -------------- |
| Special npm command   | Custom script  |
| Doesn't require `run` | Requires `run` |

---

### Can one npm script call another?

Yes.

Example:

```json
{
  "scripts": {
    "build": "vite build",
    "deploy": "npm run build"
  }
}
```

# Interview Answer

> **NPM Scripts are custom commands defined in the `scripts` section of `package.json`. They simplify development by providing reusable commands for tasks such as starting the application, running tests, building the project, linting code, and formatting files. When an npm script runs, npm automatically makes executables from `node_modules/.bin` available, allowing locally installed tools like ESLint, Vite, or Jest to be used without global installation. NPM Scripts improve consistency across development teams and are widely used in modern JavaScript and Node.js projects.**
