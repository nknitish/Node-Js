# Node.js `package.json`

> **Interview Definition:**
> The **`package.json`** file is the heart of every Node.js project. It contains metadata about the project, manages dependencies, defines scripts, specifies the project entry point, and provides configuration used by npm and other tools.

# 1. What is package.json?

Every Node.js project contains a **package.json** file.

Example:

```text
my-project/

│

├── package.json

├── package-lock.json

├── node_modules/

└── src/
```

Think of it as the **blueprint** of your project.

It tells npm:

- Project name
- Version
- Dependencies
- Scripts
- Entry point
- Module type
- Author
- License

---

# 2. Why Do We Need It?

Without `package.json`:

❌ No dependency management

❌ No npm scripts

❌ Difficult project setup

❌ Hard to share the project

With `package.json`:

```text
Git Clone

↓

npm install

↓

Everything Works
```

# 6. Important Fields

## name

Project name.

```json
{
  "name": "node-interview"
}
```

Rules:

- lowercase
- no spaces
- unique if publishing

---

## version

Semantic Versioning (SemVer).

```json
{
  "version": "1.2.3"
}
```

Meaning:

```text
Major.Minor.Patch

1 . 2 . 3
```

### Major

Breaking changes

### Minor

New features

### Patch

Bug fixes

---

## description

```json
{
  "description": "Node.js Interview Notes"
}
```

---

## main

Entry point.

```json
{
  "main": "index.js"
}
```

When someone imports your package:

```js
import demo from "my-package";
```

Node loads:

```text
index.js
```

unless `exports` overrides it.

---

## type

Defines module system.

CommonJS

```json
{
  "type": "commonjs"
}
```

ES Modules

```json
{
  "type": "module"
}
```

---

## author

```json
{
  "author": "Nitish Kumar"
}
```

---

## license

```json
{
  "license": "MIT"
}
```

Common licenses:

- MIT
- ISC
- Apache-2.0

---

## private

```json
{
  "private": true
}
```

Prevents accidental publishing to npm.

# 7. dependencies

Packages required in production.

```json
{
  "dependencies": {
    "express": "^5.0.0",
    "mongoose": "^8.0.0"
  }
}
```

Install:

```bash
npm install express
```

---

# 8. devDependencies

Packages used only during development.

```json
{
  "devDependencies": {
    "jest": "^30.0.0",
    "eslint": "^9.0.0"
  }
}
```

Install:

```bash
npm install -D jest
```

Examples:

- Jest
- ESLint
- TypeScript
- Prettier
- Nodemon

---

# 9. Scripts

One of the most important sections.

```json
{
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest",
    "lint": "eslint .",
    "build": "webpack"
  }
}
```

Run:

```bash
npm run dev
```

Special scripts:

```bash
npm start

npm test
```

These don't require `run`.

---

# 10. exports

Controls what consumers of your package can import.

```json
{
  "exports": {
    ".": "./index.js"
  }
}
```

Benefits:

- Encapsulation
- Cleaner public API
- Better package organization

---

# 11. engines

Specify supported Node.js versions.

```json
{
  "engines": {
    "node": ">=20"
  }
}
```

---

# 12. bin

Used for CLI tools.

```json
{
  "bin": {
    "mycli": "./index.js"
  }
}
```

Run:

```bash
mycli
```

after installing/linking the package.

# 15. Complete Example

```json
{
  "name": "node-demo",
  "version": "1.0.0",
  "description": "Node.js Demo Project",
  "private": true,
  "type": "module",

  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest",
    "lint": "eslint ."
  },
  "dependencies": {
    "express": "^5.0.0"
  },
  "devDependencies": {
    "eslint": "^9.0.0",
    "jest": "^30.0.0",
    "nodemon": "^3.0.0"
  },
  "engines": {
    "node": ">=20"
  },
  "author": "Nitish Kumar",
  "license": "MIT"
}
```

# package.json vs package-lock.json

| package.json                | package-lock.json              |
| --------------------------- | ------------------------------ |
| Lists dependency ranges     | Locks exact installed versions |
| Manually editable           | Auto-generated                 |
| Shared with project         | Shared with project            |
| Used for installation rules | Ensures reproducible installs  |

# Common Interview Questions

### What is package.json?

The configuration file that describes a Node.js project and manages dependencies, scripts, metadata, and package settings.

---

### Difference between dependencies and devDependencies?

| dependencies         | devDependencies             |
| -------------------- | --------------------------- |
| Needed in production | Needed only for development |
| Express              | ESLint                      |
| Mongoose             | Jest                        |
| Axios                | TypeScript                  |

---

### What is the purpose of scripts?

To define reusable project commands such as starting the server, running tests, linting, and building.

---

### What does `"type": "module"` do?

It tells Node.js to interpret `.js` files as ES Modules, allowing the use of `import` and `export`.

---

### Why use `"private": true`?

To prevent the package from being accidentally published to the npm registry.

---

### What is the purpose of `package-lock.json`?

It locks the exact dependency tree so that every installation uses the same package versions.

# Interview Answer

> **The `package.json` file is the central configuration file for a Node.js project. It stores project metadata, manages dependencies, defines npm scripts, specifies the entry point, and configures the module system. It also supports fields such as `exports` for controlling the public API, `engines` for specifying supported Node.js versions, and `bin` for exposing CLI commands. Together with `package-lock.json`, it ensures consistent dependency management and makes projects easy to install, run, and maintain.**
