# Peer Dependencies in Node.js

> **Interview Definition:**
> **Peer Dependencies** are packages that your library expects the **consumer (the application using your library)** to install. Unlike `dependencies`, they are **not bundled as your library's own runtime dependency**. They are commonly used by plugins and reusable libraries to ensure compatibility with a specific version of another package.

# 1. What are Peer Dependencies?

Imagine you're building a React component library.

Your library uses React internally.

Should your library install React?

**No.**

Instead, your library expects the application using it to already have React installed.

That's exactly what **peerDependencies** are for.

---

# 2. Why Do We Need Peer Dependencies?

Suppose we publish:

```text
awesome-ui-library
```

Internally it uses:

```text
React
```

Now imagine an application already has:

```text
React 19
```

If our library also installs its own copy:

```text
App

↓

React 19

↓

Library

↓

React 18
```

Now two React versions exist.

Problems:

- Hooks may fail
- Context may not work correctly
- Bundle size increases
- Unexpected bugs

Instead:

```text
Application

↓

React 19

↓

Our Library

↓

Uses the same React instance
```

---

# 3. How Peer Dependencies Work

```text
Application

↓

npm install react

↓

npm install awesome-ui-library

↓

Library checks

↓

Is React installed?

↓

Yes

↓

Use existing React
```

---

# 4. package.json Example

```json
{
  "name": "awesome-ui-library",
  "peerDependencies": {
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  }
}
```

Notice:

There is **no React inside `dependencies`**.

The application provides React.

---

# 5. Installing the Library

Consumer installs:

```bash
npm install react react-dom
```

Then:

```bash
npm install awesome-ui-library
```

Everything works because React already exists.

---

# 6. What Happens If React Isn't Installed?

Suppose the user runs:

```bash
npm install awesome-ui-library
```

but forgets:

```bash
npm install react
```

npm may display a warning or fail depending on the package manager and configuration, because the required peer dependency is missing.

# 7. dependencies vs peerDependencies

| dependencies                | peerDependencies                            |
| --------------------------- | ------------------------------------------- |
| Installed with your package | Expected to be installed by the consumer    |
| Used by applications        | Commonly used by reusable libraries/plugins |
| Own copy is installed       | Shares the consumer's copy                  |

# 9. Why Not Put React in `dependencies`?

Bad:

```json
{
  "dependencies": {
    "react": "^19.0.0"
  }
}
```

Possible result:

```text
Application

↓

React

↓

Library

↓

Another React
```

This can lead to multiple React instances.

Better:

```json
{
  "peerDependencies": {
    "react": "^19.0.0"
  }
}
```

One React instance shared by both.

---

# 10. `peerDependenciesMeta`

Optional peer dependencies can be declared using:

```json
{
  "peerDependencies": {
    "typescript": "^5.0.0"
  },
  "peerDependenciesMeta": {
    "typescript": {
      "optional": true
    }
  }
}
```

This tells npm that the peer dependency is optional.

# 12. Common Interview Questions

### What are Peer Dependencies?

Packages that a library expects the consuming project to install and provide.

---

### Why use Peer Dependencies?

To avoid duplicate installations and ensure compatibility with the host application's version.

---

### Should applications use Peer Dependencies?

Usually **no**.

Applications typically use:

- dependencies
- devDependencies

Peer dependencies are mainly for reusable libraries and plugins.

---

### Why do React libraries use Peer Dependencies?

Because the application should provide a single shared React instance.

---

### Difference between dependencies and peerDependencies?

| dependencies             | peerDependencies           |
| ------------------------ | -------------------------- |
| Installed automatically  | Expected from the consumer |
| Runtime dependency       | Compatibility requirement  |
| Can have multiple copies | Intended to share one copy |

---

# 13. Quick Revision

| Type             | Installed By                 |
| ---------------- | ---------------------------- |
| dependencies     | npm installs automatically   |
| devDependencies  | npm installs for development |
| peerDependencies | Consumer installs            |

# Interview Answer

> **Peer Dependencies are packages that a library expects the consuming application to install. They are commonly used by plugins and reusable libraries, such as React component libraries, ESLint plugins, and Vite plugins, to ensure compatibility with a single shared version of another package. This avoids duplicate installations, reduces bundle size, and prevents issues that can arise when multiple versions of the same framework or tool are loaded.**
